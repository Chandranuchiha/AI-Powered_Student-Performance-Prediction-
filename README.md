# AI-Powered Student Performance Prediction (Project 02)

Predicts whether a student will **pass** (final_score >= 50) from mid-term academic indicators, so educators can plan early support. Prototype on **synthetic data only**.

## Structure
| Path | Purpose |
|---|---|
| `app.py` | Streamlit UI (5 tabs) |
| `config.py` | Columns, ranges, seed, pass mark |
| `studentperf/validation.py` | File/column/type/range checks |
| `studentperf/preparation.py` | Cleaning + transformation log |
| `studentperf/model.py` | Split, models, metrics, errors (no UI code) |
| `generate_data.py` | Builds synthetic CSV (seed 42) |
| `tests/test_core.py` | 14 tests |
| `Student_Performance_Colab.ipynb` | Self-contained Colab version |
| `data/raw/` | Raw input, never modified; outputs go to `outputs/` or downloads |

## Setup & run
```
pip install -r requirements.txt
python generate_data.py          # optional, CSV is already included
streamlit run app.py
pytest -q tests
```
**Colab:** upload `Student_Performance_Colab.ipynb`, Runtime > Run all (last cell optionally serves the Streamlit app).

## Demo workflow
1. Open app, tick *Use bundled synthetic sample* (or upload your CSV).
2. **Data quality**: see duplicates removed, missing values, transformation log.
3. **Trends**: box plots by outcome, correlations with final score.
4. **Evaluation**: metrics, confusion matrix, feature factors, confident errors.
5. **Predict a student**: enter values, get pass probability.
6. **Cohort & export**: at-risk list, download CSVs.

## Data dictionary (CSV input)
`student_id` (text, unique) · `attendance_pct` 0-100 · `study_hours_week` 0-80 · `prior_gpa` 0-10 · `assignment_avg` 0-100 · `midterm_score` 0-100 · `participation_score` 0-10 · `final_score` 0-100 (used to derive target `passed`).

**Source/licence:** fully synthetic, generated by `generate_data.py`; no real students; free to use. Contains deliberate defects (25 missing cells, 5 duplicate rows) to exercise quality checks.

## Method
- Preparation: dedupe, drop missing target / out-of-range rows, derive target. Missing features median-imputed **inside the pipeline, fit on training data only** (no leakage).
- Split: 64/16/20 train/val/test, stratified, seed 42. Baseline: Logistic Regression (standardised). Comparison: Random Forest.
- Explainability: logistic coefficients / RF importances; most confident test errors shown.

## Results (test set, n=120, seed 42, actual run)
| Model | Accuracy | Precision | Recall | F1 | ROC-AUC |
|---|---|---|---|---|---|
| Logistic Regression | 0.917 | 0.957 | 0.938 | 0.947 | 0.967 |
| Random Forest | 0.933 | 0.958 | 0.958 | 0.958 | 0.975 |

Strongest factors (logreg): midterm_score, assignment_avg, study_hours_week, attendance_pct, prior_gpa.

## Testing
`pytest -q tests` -> 14 passed (validation, empty/header-only files, bad types, out-of-range, duplicates, repeatability, target definition, baseline comparison, missing-value prediction, sanity ordering).

## Limitations
- Synthetic data: the target is generated from the same features, so high scores **do not indicate real-world accuracy**.
- Small test set (120) -> wide uncertainty; associations are not causes.
- Final-exam-adjacent features (mid-term, assignments) limit how early it can warn; no fairness audit by demographic group (none in data).
- Use only anonymised/authorised data; the app keeps nothing on disk (uploads live in session memory).

## Future work
Time-aware validation on real multi-semester data, probability calibration, SHAP explanations, fairness checks, early-warning model with fewer features.
